# 准入与隐私三层门锁：微信后台与云开发设置清单

本文档只列**必须人工在微信公众平台 / 云开发控制台完成**的设置项。代码侧已经做到的部
分放在最后一节，便于区分「改代码能解决」和「只能后台解决」。

> 菜单文案会随微信后台版本变化，位置以「设置 / 管理 / 功能」一级菜单为准；找不到时
> 在对应一级菜单内搜索关键词（搜索、收录、成员、体验、隐私、权限）。

---

## 一、第一层：外部不可达（微信公众平台）

### 1. 关闭被搜索与页面收录

- 位置：微信公众平台 → 设置 → 基本设置 → 隐私设置 / 搜索设置（部分版本叫「页面收录设置」）
- 操作：关闭「允许通过名称搜索到小程序」「允许页面被微信索引 / 收录」
- 作用：外部用户在微信搜一搜、小程序搜索里找不到本小程序。
- 备注：代码侧 `miniprogram/sitemap.json` 已把所有页面设为 `disallow`，两者叠加；
  只改代码不关后台开关，仍可能被名称搜到。

### 2. 关闭「附近的小程序」

- 位置：微信公众平台 → 功能 → 附近的小程序
- 操作：不开启；如已开启则取消发布 / 删除地点
- 作用：附近推荐、线下扫码推荐不会把外部人带进来。

### 3. 收紧成员与体验成员

- 位置：微信公众平台 → 管理 → 成员管理 → 项目成员 / 体验成员
- 操作：只保留俱乐部内部人员；移除离职人员、外部测试人员
- 作用：非内部微信无法打开开发版、体验版；这是体验阶段最重要的一道门。

### 4. 版本发布策略

- 位置：微信公众平台 → 管理 → 版本管理
- 操作：只保留体验版给内部人员；不要提交审核 / 不要发布线上版。
  如业务必须发布线上版，则完全依赖第二层的邀请门锁，且必须完成第 1、2、3 项。
- 作用：外部没有公开入口；即使拿到体验版链接，也会被准入页拦截。

### 5. 分享传播

- 代码侧已做：所有页面 `onLoad` 调用 `wx.hideShareMenu`，隐藏「发送给朋友」和
  「分享到朋友圈」；项目没有定义 `onShareAppMessage` / `onShareTimeline`，分享链接
  不会携带 `athleteId`、姓名等敏感参数。
- 后台侧：微信后台没有全局「关闭分享」开关；如账号后台出现「分享设置」入口，
  一并关闭「允许分享到朋友圈 / 允许转发」。
- 作用：页面右上角不再出现转发入口；即使旧版本残留分享菜单，链接里也没有业务参数，
  打开后仍会被准入页拦截。

### 6. 小程序码 / 二维码

- 位置：微信公众平台 → 管理 → 小程序码 / 二维码
- 操作：不对外投放、不印刷到公开物料；只通过内部群、内部纸质物料分发。
- 作用：减少外部人拿到入口的概率。

### 7. 广告、流量主与第三方

- 位置：微信公众平台 → 流量主 / 广告主；设置 → 第三方设置
- 操作：不开通流量主/广告；不绑定不必要的第三方平台、不接入第三方统计 SDK。
- 作用：避免数据被第三方收集，也避免小程序被公开推荐。

### 8. 用户隐私保护指引

- 位置：微信公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引
  （部分版本在「设置 → 隐私与安全」）
- 操作：声明收集范围：微信 openid、身高/体重/目标体重、饮食记录、训练与睡眠、
  餐食照片；用途写明「俱乐部内部营养支持」，不对外共享。
- 作用：合规必需；不填会影响隐私接口与审核。

## 二、云开发控制台设置（必须手工）

### 1. 数据库权限

- 位置：云开发控制台 → 数据库 → 选择集合 → 权限设置
- 操作：**所有集合统一设为「所有用户不可读写」**
  （`users`、`logs`、`messages`、`inbox`、`followups`、`reminders`、`rule_reviews`、
  `settings`、`pair_codes`、`phase_history`）。
- 作用：
  - 客户端无法绕过云函数直接读任何集合；
  - 客户端无法直接改自己 `users` 文档里的 `role` / `coachOpenid`，
    否则「仅创建者可读写」会让任何人都能把自己改成教练。
- 备注：本项目小程序端没有任何 `wx.cloud.database()` 直连，全部走云函数；
  云函数使用管理员权限，因此归属校验必须在代码里做（代码里已做）。
- 如果为了 `messages` 实时 watch 改成自定义规则，必须保留
  `read: "doc._openid == auth.openid"` 这类按人隔离条件，且 `write` 只允许 false。

### 2. 云存储权限

- 位置：云开发控制台 → 存储 → 权限设置
- 操作：设为 **仅创建者可读写**
- 作用：餐食照片不会通过公开 URL 被外部读取；`visionFood` 只在云函数内下载。

### 3. 云函数访问方式

- 位置：云开发控制台 → 云函数 → 各函数配置
- 操作：不要开启 HTTP 触发 / 公网访问；只允许小程序端 `wx.cloud.callFunction`。
- 作用：外部无法直接 HTTP 调用云函数绕过小程序准入页。

### 4. settings 集合的两个码

在云开发控制台 → 数据库 → `settings` 集合中维护：

| key | 作用 | 建议 |
| --- | --- | --- |
| `coachCode` | 旧版邀请码，兼容历史，只授予 athlete | 可保留，但不要外传 |
| `coachActivationCode` | 教练激活码，**唯一能授予 coach 角色** | 必须配置，且与 `coachCode` 不同；只发给内部教练 |

- 不配置 `coachActivationCode` 时，新的教练账号无法自助激活（会提示未配置）。
  已存在的 `role: 'coach'` 老账号不受影响。
- 作用：角色由服务端根据「码属于哪一类」判定；前端页面的「我是拳王/我是教练」只切换
  输入提示，不能决定身份。

### 5. 云函数重新部署

本次改动了以下云函数，必须重新部署后才生效：

`whoami`、`bind`、`getFeed`、`inbox`、`chat`、`coachApi`、`saveLog`、`saveProfile`、
`visionFood`。

`advice` 云函数契约未改动，不需要因本次改动重新部署（如代码有其它变更按正常流程部署）。

## 三、代码侧已经做到（不需要后台操作）

- `miniprogram/sitemap.json`：所有页面 `disallow`，不参与微信索引。
- 全部页面 `onLoad` 调用 `wx.hideShareMenu`，禁用转发/朋友圈菜单。
- 未定义 `onShareAppMessage` / `onShareTimeline`，不存在带业务参数的分享链接。
- 新增 `pages/admission/admission`：未准入用户只能看到「仅限内部使用」说明与配对码入口。
- `whoami` 首次进入只创建 `admission: 'pending'` 的待准入账号，不再默认可用。
- 所有业务云函数对 `admission !== 'active'` 返回 `PENDING_ADMISSION`。
- `bind` 只按码的类型授予角色，忽略前端传入的 `asCoach` / `role`。
- 读接口归属校验：拳王按 `OPENID` 锁定，教练按 `coachOpenid` 校验；解绑后不再返回
  旧拳王的收件箱内容。
- 教练端按 `athleteId` 隔离的离线缓存增加了归属过滤；本机建议缓存增加 `owner` 校验。

## 四、上线验收清单

| # | 验收项 | 操作 | 期望 |
| --- | --- | --- | --- |
| 1 | 外部搜索 | 用未加入成员的微信搜小程序名称 | 搜不到 |
| 2 | 外部打开 | 用未加入成员的微信打开体验版/链接 | 只看到「仅限内部使用」准入页 |
| 3 | 新用户 | 首次打开小程序 | 只看到准入页，看不到任何业务页面 |
| 4 | 拳王升级 | 已绑定拳王更新版本后进入 | 直接进入首页，记录/建议正常 |
| 5 | 教练升级 | 已绑定教练更新版本后进入 | 直接进入教练端，名下拳王正常 |
| 6 | 未绑定老用户 | 升级前打开过、但从未绑定 | 进入准入页，需配对码 |
| 7 | 角色伪造 | 拳王在页面参数里传 `athleteId` / `role` | 服务端按本人身份返回，不泄露他人 |
| 8 | 教练解绑后 | 教练解绑某拳王后再看收件箱 | 不再出现该拳王的消息 |
| 9 | 分享菜单 | 任意页面右上角「…」 | 无「发送给朋友 / 分享到朋友圈」 |
| 10 | 直接读库 | 开发者工具直接 `wx.cloud.database()` 读 `logs` | 被数据库权限拒绝 |

## 五、推荐上线顺序

1. 在 `settings` 配置 `coachActivationCode`（与 `coachCode` 不同）。
2. 部署本次改动的云函数。
3. 上传小程序代码，先设为体验版。
4. 后台关闭搜索/收录、附近的小程序；收紧成员管理。
5. 按第四节验收清单逐项测试。
6. 真机与云端部署行为需在体验版上实际验证；当前代码只做了静态检查与既有测试。

## 六、已知未验证 / 风险

- 微信后台菜单文案与开关位置可能随版本变化，本文档按常见位置描述，需以后台实际界面为准。
- 真机上的分享菜单隐藏、准入页跳转、云端 `whoami` 返回状态均**未在真机验证**。
- 老用户兼容按「有 `coachOpenid` / `coachCode` 或 `role: 'coach'` 即视为已准入」判定；
  从没绑定过的老用户会被要求输入配对码，这是预期行为，但上线前需通知内部用户。
- 旧版本遗留的本机建议缓存没有 `owner` 字段，无法追溯账号；新写入的缓存都会带
  `owner`，换账号后会被拒绝读取。
